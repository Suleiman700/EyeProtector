# Master Enable/Disable Toggle — Design Spec

**Date:** 2026-07-29
**Status:** Approved, implementing

## Goal

A single master switch that turns the whole app on or off. When **off**, nothing runs:
breaks, blink reminders, and wellness reminders all stop, any overlay currently on screen
closes, the tray countdown disappears, and the tray icon changes to a disabled (slashed)
look. The switch lives both **in the app** (a global header pill visible on every
preferences page) and **in the tray menu**, and both reflect the same state.

## Scope note

This is sub-project **#1 (master toggle)** of a five-feature batch. The others —
multi-monitor overlays/toasts, global keyboard shortcuts (#35), DND/OS integration (#40),
battery-saver mode (#46) — are **out of scope here** and get their own specs. Build order:
master toggle first (it gates all the others), then multi-monitor, then #35/#40/#46.

## Decisions (confirmed with author)

- **OFF semantics:** full stop + close active. Stop all schedulers, close any overlay/banner
  currently on screen immediately, hide the tray countdown, switch the tray icon to disabled.
  Turning back **ON restarts all timers fresh** (no resume-from-remaining).
- **In-app placement:** a global header pill in the top bar, visible on every page. When off,
  the countdown hides and a slim "paused" banner shows above the page content.
- **Tray:** icon changes with state; a checkbox menu item toggles it; "Take a break now" and
  the countdown row are hidden while disabled.

## Data Model — `src/shared/settings.ts`

Add `enabled: boolean` to `AppSettings`, default `true`. `SettingsStore.get()` already merges
over `DEFAULT_SETTINGS`, so files written before this key existed read back as enabled.

```ts
export interface AppSettings {
  enabled: boolean
  // …existing fields…
}
export const DEFAULT_SETTINGS: AppSettings = {
  enabled: true,
  // …
}
```

## Main-process Coordinator — `src/main/index.ts`

A single `applyEnabled(s: AppSettings)` reacting only to **transitions** of `s.enabled`,
tracked with a previous-value guard so ordinary preference edits (interval changes, etc.) do
not restart timers:

```ts
let enabledNow = settings.get().enabled
const applyEnabled = (s: AppSettings): void => {
  if (s.enabled) {
    controller.start()
    blinkController.start()
    reminderController.start()
  } else {
    controller.stop()
    blinkController.stop()
    reminderController.stop()
    overlay.close()
    blinkOverlay.close('completed')
    reminderPresenter.handleAction('skip')
    broadcastStatus({ status: 'disabled', msUntilNext: -1 })
  }
  tray.setEnabled(s.enabled)
}
applyEnabled(settings.get())              // replaces the unconditional *.start() calls
settings.onChange((s) => {
  if (s.enabled !== enabledNow) {
    enabledNow = s.enabled
    applyEnabled(s)
  }
})
```

Notes:
- Replaces the three unconditional `controller.start()` / `blinkController.start()` /
  `reminderController.start()` calls at the end of `app.whenReady()`.
- The controllers' own `settings.onChange` subscriptions (engine reconfigure / reschedule)
  still fire while disabled but are harmless because their tickers are stopped; `start()` on
  re-enable resets everything.
- Closing calls are all guard-safe when nothing is showing (`overlay.close()`,
  `BlinkOverlay.close()` early-returns when no window, `ReminderPresenter` close early-returns
  when `!win`).
- `msUntilNext: -1` reuses the existing "no break enabled" convention so the tray/header
  countdown hides with no new status field.

## Tray — `src/main/TrayController.ts`

- Store `enabled` state; add `setEnabled(enabled: boolean)`:
  - swaps the icon between `trayTemplate.png` and `trayDisabledTemplate.png` (both template
    images) via `nativeImage.createFromPath` + `setTemplateImage(true)` + `tray.setImage(...)`,
  - re-renders the menu.
- `TrayHandlers` gains `setEnabled(enabled: boolean): void`, wired in `index.ts` to
  `settings.set({ enabled })` (which flows back through `applyEnabled` and updates the app).
- Menu changes:
  - New checkbox item **"Enable EyeProtector"** (`type: 'checkbox'`, `checked: enabled`,
    click → `handlers.setEnabled(!enabled)`), placed at the top.
  - While disabled, omit the "Take a break now" item and the countdown row.
- `setCountdown` is a no-op display-wise while disabled (the coordinator already broadcasts
  `msUntilNext: -1` on disable, and re-enable resumes normal countdown broadcasts).

## Disabled Tray Icon — `resources/trayDisabledTemplate.png` (+ `@2x`)

The existing closed-eyes glyph with a diagonal slash, kept as a macOS template image (black +
alpha only) so the menu bar inverts it for light/dark automatically. Generated by a committed
**dependency-free** Node script `resources/gen-tray-icons.mjs` that uses only Node built-ins
(`zlib`): it decodes the existing `trayTemplate.png` / `@2x` (8-bit RGBA, PNG filter unfilter
via `zlib.inflateSync`), draws an opaque diagonal slash across the glyph, and re-encodes
(filter 0 scanlines, `zlib.deflateSync`, CRC32 chunks) to `trayDisabledTemplate.png` and
`@2x`. No new npm dependency is added (org policy: only approved packages). The generated
16px and 32px PNGs are committed alongside the script.

## Preferences UI — global header pill (`src/renderer/preferences/App.tsx`)

The top bar currently shows only the "Next break" countdown on the right. Add, on the left, a
master pill: the text `EyeProtector` plus the existing `Switch`, bound to `settings.enabled`
via the existing `useSettings()` `update({ enabled })`.

- When `settings.enabled` is false:
  - hide the countdown pill,
  - render a slim banner directly under the header:
    `"EyeProtector is paused — nothing will run until you turn it back on."`
- The header already has `settings` in scope (App loads it via `useSettings`). No new IPC:
  toggling the pill calls `update({ enabled })`, which persists and propagates to the main
  process and tray through the normal settings-change path.

## Testing

This feature is Electron orchestration (start/stop + window/tray side effects), so it is
verified by running the app rather than unit tests:

- Toggle off (header or tray) → break/blink/reminder timers stop; an overlay on screen closes
  immediately; tray icon switches to the slashed variant; tray countdown row and
  "Take a break now" disappear; header countdown hides and the paused banner appears.
- Toggle on → all timers restart fresh; tray icon returns to normal; countdown reappears.
- Header pill and tray checkbox always show the same state (change one, the other updates).

The only new pure value is the `enabled` default, covered by the existing settings
merge-over-defaults behavior.
